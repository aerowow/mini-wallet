# ТЗ: История

**Автор:** PM (jwynana) · **Исполнитель:** Dev 3 · **Ветка:** feature/history · **Статус:** draft

## 1. Назначение экрана

Список всех операций пользователя с группировкой по дням, поиском и фильтрами.
Только чтение: операции отсюда не создаются, не редактируются и не удаляются.

## 2. Данные из общего контракта

Ниже — что экрану нужно по продукту. Устройство моделей и API — в контракте `Core`
(PR `core/contract`), экран его не диктует.

Экрану нужны:
- список всех операций пользователя; по каждой — дата и время, тип (перевод
  или пополнение), участвующие счета, сумма, валюта, комментарий, успешность
  и причина ошибки для неуспешной (показывается в подписи строки);
- порядок: по убыванию даты и времени, сначала новые;
- названия счетов — для показа в строке и для фильтра по счёту;
- появление нового успешного перевода в списке сразу, без перезапуска приложения;
- стартовые мок-данные — семь операций из таблицы ниже, с датами относительно
  текущего дня, чтобы группы «Сегодня» и «Вчера» оставались корректными;
- единый на все три экрана формат вывода денег: `128 450,00 ₽`;
- переход на вкладку «Перевод».

## 3. UI и состояния

Сверху вниз:
1. Заголовок «История».
2. Поле поиска, плейсхолдер «Поиск по комментарию и сумме».
3. Ряд фильтров-чипов: «Все», «Входящие», «Исходящие», «Счёт», «Период».
   Активный фильтр подсвечен; при активных фильтрах рядом счётчик и действие «Сбросить».
4. Список, сгруппированный по дням с липкими заголовками. Строка: иконка направления,
   «Основной → Накопительный», комментарий и время подписью, сумма справа.
   У неуспешной операции в подписи вместо комментария — причина ошибки,
   плюс бейдж «Ошибка».
5. Таб-бар с активной вкладкой «История».

Таб-бар — часть интерфейса экрана, но **корневой `TabView` реализуется отдельно
владельцем корневых файлов проекта** и в задачу Dev 3 не входит. Механизм программного
переключения вкладок готовится в том же корневом PR до начала параллельной разработки фич.

### Порядок и группировка

Операции идут по убыванию даты и времени: сначала новые. Внутри одного дня —
от поздних к ранним. Заголовки групп: «Сегодня», «Вчера», далее дата вида «26 августа».

### Суммы

- Исходящие — со знаком минус, нейтральным цветом.
- Входящие — со знаком плюс, цветом `positive`.
- **Неуспешная операция — без плюса и минуса**, деньги по ней не списаны;
  дополнительно показывается бейдж «Ошибка». Красный цвет — только для ошибок.

### Поиск

- Работает только по комментарию и по сумме. По названию счёта поиск не выполняется.
- По комментарию — без учёта регистра.
- По сумме — пробелы-разделители разрядов не учитываются
  (запрос `5000` и `5 000` находят одно и то же).

### Фильтры

- Направление: **пополнения считаются входящими, все переводы между счетами —
  исходящими**. Это упрощённое правило учебного MVP: каждый перевод показан одной
  строкой со знаком минус. Неуспешная операция тоже относится к «Исходящим»: фильтр
  отражает направление операции, а не факт списания.
- Шит фильтров: тип операции, счёт (Все / Основной / Накопительный / Валютный),
  период (Сегодня / 7 дней / 30 дней / Всё время), кнопки «Применить» и «Сбросить».
- Поиск и выбранные фильтры применяются **одновременно, по принципу «И»**.
- Счётчик активных фильтров показывает число изменённых групп: тип, счёт, период.
  Поисковый запрос в счётчик не входит.
- **Быстрые чипы применяются сразу.** Изменения внутри шита — черновые: «Применить»
  сохраняет их, закрытие шита свайпом без применения отменяет. При открытии шит
  показывает текущие применённые фильтры.
- Тип операции — одно значение: применённый выбор в чипах и в шите всегда совпадает.

Сброс:

| Действие | Что сбрасывается |
|---|---|
| Верхний чип «Все» | тип, счёт и период; поисковый запрос сохраняется |
| Значение «Все» внутри выбора типа в шите | только тип операции |
| «Сбросить» рядом с активными фильтрами | только фильтры; поисковый запрос сохраняется |
| Кнопка в состоянии «Ничего не найдено» | и поисковый запрос, и все фильтры — возвращается полный список |

### Состояния

- **Обычное** — все семь мок-операций, включая одну неуспешную.
- **Фильтры** — шит выбора, описан выше.
- **Ничего не найдено** — «Ничего не найдено», «Измените запрос или сбросьте фильтры»,
  кнопка «Сбросить фильтры».
- **Нет операций** — «Операций пока нет», «Здесь появятся ваши переводы и пополнения»,
  кнопка «Сделать перевод», которая переключает на вкладку «Перевод». Поиск и фильтры скрыты.

Мок-операции:

| Когда | Операция | Сумма | Статус | Комментарий |
|---|---|---|---|---|
| Сегодня, 14:32 | Перевод: Основной → Накопительный | −5 000,00 ₽ | выполнено | Отложить на отпуск |
| Сегодня, 11:05 | Перевод: Основной → Валютный | 10 000,00 ₽ | ошибка «Разные валюты счетов» | — |
| Вчера, 19:48 | Пополнение: Основной | +32 000,00 ₽ | выполнено | Зарплата |
| Вчера, 09:12 | Перевод: Накопительный → Основной | −1 500,00 ₽ | выполнено | Продукты |
| 26 августа, 21:03 | Перевод: Основной → Накопительный | −12 000,00 ₽ | выполнено | — |
| 26 августа, 08:40 | Пополнение: Накопительный | +7 000,00 ₽ | выполнено | Кэшбэк |
| 24 августа, 16:20 | Перевод: Основной → Накопительный | −3 200,00 ₽ | выполнено | Резерв |

Неуспешная операция между счетами разных валют существует **только в стартовых
мок-данных** и оставлена, чтобы продемонстрировать это состояние истории. Новые такие
операции не создаются: перевод блокируется валидацией на экране перевода.

Новая запись в истории создаётся **только после успешного перевода**. Ошибки валидации,
ошибка выполнения и повтор уже выполненной операции записей не создают.

Стартовые балансы счетов и стартовая история задаются независимо: история — пример
последних операций, а не полный реестр, из которого рассчитываются балансы.

## 4. Критерии приёмки

- Дано: семь мок-операций. Когда: открыт экран. Тогда: показаны все семь, сгруппированы
  по дням, заголовки «Сегодня», «Вчера», «26 августа», «24 августа», внутри дня —
  от поздних к ранним.
- Дано: список открыт. Когда: смотрим на неуспешную операцию. Тогда: бейдж «Ошибка»,
  сумма без плюса и минуса, в подписи — причина «Разные валюты счетов».
- Дано: поиск «ОТПУСК». Тогда: найдена операция от «Сегодня, 14:32» — регистр не влияет.
- Дано: поиск «5000». Тогда: найдена операция на `5 000,00 ₽`.
- Дано: поиск «Основной». Тогда: по названию счёта ничего не находится.
- Дано: фильтр «Входящие». Тогда: показаны только два пополнения.
- Дано: фильтр «Исходящие». Тогда: показаны только переводы между счетами.
- Дано: фильтр по счёту «Накопительный». Тогда: только операции, где он источник
  или получатель.
- Дано: активны поиск и фильтр одновременно. Тогда: условия складываются по «И»,
  счётчик показывает число изменённых групп фильтров без учёта поиска.
- Дано: в чипах выбрано «Входящие». Когда: открыт шит фильтров. Тогда: в шите показан
  тот же тип.
- Дано: в шите изменены счёт и период. Когда: шит закрыт свайпом без «Применить».
  Тогда: список и активные фильтры не изменились.
- Дано: в шите изменены счёт и период. Когда: нажато «Применить». Тогда: список
  отфильтрован, счётчик показывает две изменённые группы.
- Дано: активен фильтр «Входящие» и выбран счёт. Когда: нажат верхний чип «Все».
  Тогда: сброшены тип, счёт и период; поисковый запрос остался.
- Дано: активны поиск и фильтры. Когда: нажат чип «Все» или «Сбросить».
  Тогда: фильтры сброшены, поисковый запрос остался.
- Дано: поиск «такси». Тогда: «Ничего не найдено»; нажатие кнопки очищает и поиск,
  и фильтры и возвращает полный список.
- Дано: операций нет. Тогда: «Операций пока нет», поиск и фильтры скрыты;
  «Сделать перевод» переключает на вкладку «Перевод».
- Дано: выполнен новый перевод. Когда: открыт экран истории. Тогда: операция показана
  первой, без перезапуска приложения.

Детали операции отдельным шитом — необязательная часть, «если останется время».
В обязательные критерии приёмки не входит.

## 5. Вне скоупа

Авторизация и регистрация, онбординг, настройки, профиль, внешние переводы по номеру
карты, конвертация валют, iPad и ландшафт, анимации и переходы, тёмная тема.
