# ТЗ: Перевод

**Автор:** PM (jwynana) · **Исполнитель:** Dev 2 · **Ветка:** feature/transfer · **Статус:** draft

## 1. Назначение экрана

Перевод между собственными счетами пользователя. Ключевая механика — **идемпотентность**:
у каждой попытки перевода есть скрытый ключ операции, и повторный вызов одной операции
с тем же ключом не создаёт новую транзакцию и не меняет балансы повторно, а возвращает
результат первоначального перевода.

## 2. Данные из общего контракта

Ниже — что экрану нужно по продукту. Устройство моделей и API — в контракте `Core`
(PR `core/contract`), экран его не диктует.

Экрану нужны:
- список счетов пользователя; по каждому — название, маскированный номер, валюта
  и баланс. «Доступно» на этом экране — то же значение, что баланс на экране «Счета»;
  отдельного доступного баланса в MVP нет;
- выполнение перевода между двумя счетами на заданную сумму с необязательным
  комментарием, с ключом операции;
- **гарантия идемпотентности**: повторный вызов одной операции с тем же ключом
  не создаёт новую транзакцию, не меняет балансы повторно и возвращает результат
  первоначального перевода;
- различимые исходы попытки: перевод выполнен · это повтор уже выполненного перевода ·
  выполнить не удалось;
- данные первоначальной операции для показа при повторе: дата, время, сумма, счета;
- обновлённые балансы обоих счетов после успешного перевода;
- управляемая конфигурация, воспроизводящая состояния «ошибка выполнения» и «перевод
  уже выполнен», — **только в DEBUG и Preview**. В обычном продуктовом интерфейсе
  тестовых переключателей нет. Скрытые триггеры по сумме или тексту комментария
  использовать нельзя; способ управления выбирают разработчики;
- единый на все три экрана формат вывода денег: `128 450,00 ₽`;
- переход на вкладку «История».

## 3. UI и состояния

Форма сверху вниз:
1. Заголовок «Перевод».
2. Строка «Откуда» — по умолчанию «Основной •• 4417», справа доступный баланс.
3. Кнопка-иконка «поменять местами».
4. Строка «Куда» — по умолчанию не выбран, плейсхолдер «Выберите счёт».
5. Поле «Сумма» в валюте счёта-источника, под ним подпись «Доступно: …».
6. Поле «Комментарий» — необязательное, максимум 100 символов.
7. `PrimaryButton` «Перевести», прижата к низу контента.
8. Таб-бар с активной вкладкой «Перевод».

Таб-бар — часть интерфейса экрана, но **корневой `TabView` реализуется отдельно
владельцем корневых файлов проекта** и в задачу Dev 2 не входит. Механизм программного
переключения вкладок готовится в том же корневом PR до начала параллельной разработки фич.

### Ключ операции

- Ключ создаётся **при подтверждении валидного перевода**, перед началом выполнения.
- «Повторить» в шите ошибки использует **прежний** ключ.
- Изменение любого поля формы завершает предыдущую попытку.
- «Отмена» после ошибки выполнения тоже завершает попытку.
- Успех и показ повтора завершают попытку.
- Следующее подтверждение получает **новый** ключ — в том числе после «Отмены»,
  даже если поля не менялись.

После «Готово» шит закрывается, форма очищается, пользователь остаётся на вкладке
«Перевод». Обновлённые балансы к этому моменту уже отображаются в приложении.

После «Отмена» на ошибке выполнения шит закрывается, но заполненные поля сохраняются:
пользователь может изменить данные или снова подтвердить перевод. Следующее
подтверждение считается новой попыткой и получает новый ключ.

### Валидация

Четыре ошибки показываются непосредственно в форме, до открытия подтверждения:

| Условие | Текст |
|---|---|
| Сумма больше доступного баланса | «Недостаточно средств» |
| Сумма не больше нуля | «Введите сумму больше нуля» |
| «Откуда» и «Куда» — один счёт | «Счета должны быть разными» |
| Валюты счетов не совпадают | «Перевод между счетами в разных валютах недоступен» |

Пока есть хотя бы одна ошибка, кнопка «Перевести» неактивна и выполнение перевода
не вызывается. Валютный счёт `•• 1195` можно выбрать в «Куда»; после выбора счёта
с другой валютой показывается ошибка о разных валютах, перевод блокируется.

В рамках MVP валютный счёт нельзя использовать для успешного перевода: остальные счета
рублёвые, а переводы между разными валютами запрещены. Это осознанное ограничение.

### Состояния

- **Пустая форма** — «Куда» не выбран, сумма пустая, кнопка выключена.
- **Заполнено** — Основной → Накопительный, `5 000,00 ₽`, комментарий
  «Отложить на отпуск», кнопка активна.
- **Ошибки валидации** — текст ошибки под соответствующим полем, кнопка выключена.
- **Подтверждение** — модальный шит поверх затемнённого экрана: «Откуда», «Куда»,
  сумма, комиссия «0,00 ₽», кнопки «Подтвердить» / «Отмена».
- **Выполняется** — кнопка с индикатором и текстом «Выполняется…»; поля и кнопки
  неактивны, повторное нажатие невозможно.
- **Успех** — шит с галочкой: «Перевод выполнен», сумма, строка
  «Основной → Накопительный», новые балансы обоих счетов. Кнопки: сверху «Готово»,
  ниже «Открыть в истории».
- **Повтор уже выполненного перевода** — шит с нейтральной (не красной) иконкой:
  «Перевод уже выполнен», «Эта операция была выполнена ранее, повторно деньги
  не списаны», карточка первоначальной операции (дата, время, сумма, счета).
  Балансы не изменились, новой операции в истории нет. Кнопки: сверху «Готово»,
  ниже «Открыть в истории».
- **Ошибка выполнения** — отдельное состояние, не связанное с четырьмя ошибками
  валидации. Шит «Не удалось выполнить перевод», «Деньги не списаны, попробуйте ещё раз»,
  кнопки «Повторить» и «Отмена». Деньги при этом не списываются.
  Мок-ошибка **одноразовая**: первый вызов возвращает ошибку без списания и без создания
  операции, режим ошибки сбрасывается автоматически. «Повторить» отправляет прежний ключ,
  и следующий вызов может завершиться успешно.

Порядок кнопок в шитах успеха и повтора одинаковый: «Готово» сверху, остальные
действия ниже. Разный порядок ломает единый паттерн взаимодействия.

«Открыть в истории» переключает на вкладку «История».

Новая запись в истории создаётся **только после успешного перевода**. Ошибки валидации,
ошибка выполнения и повтор уже выполненной операции записей в истории не создают.

## 4. Критерии приёмки

- Дано: форма пустая. Когда: «Куда» не выбран или сумма пустая. Тогда: «Перевести» выключена.
- Дано: Основной → Накопительный, `5 000`. Когда: «Перевести» → «Подтвердить».
  Тогда: шит успеха, балансы `123 450,00 ₽` и `80 000,00 ₽`, в истории одна новая операция.
- **Логика стора.** Дано: перевод с ключом `K` выполнен. Когда: та же операция вызывается
  повторно с тем же ключом `K`. Тогда: создана одна операция, балансы изменены один раз,
  возвращён результат первоначального перевода. Проверяется вызовом стора, не через UI.
- **Состояние UI.** Дано: DEBUG/Preview-конфигурация «перевод уже выполнен».
  Тогда: показан шит «Перевод уже выполнен» с карточкой первоначальной операции,
  балансы не изменились, новой записи в истории нет.
- Дано: показан шит ошибки выполнения. Когда: нажата «Повторить». Тогда: уходит прежний
  ключ, режим ошибки уже сброшен, перевод выполняется успешно, создана ровно одна операция.
- Дано: сумма больше доступного баланса. Тогда: «Недостаточно средств», кнопка выключена,
  перевод не вызывается.
- Дано: «Откуда» = «Куда». Тогда: «Счета должны быть разными», кнопка выключена.
- Дано: сумма `0` или отрицательная. Тогда: «Введите сумму больше нуля», кнопка выключена.
- Дано: Основной (₽) → Валютный ($). Когда: счёт выбран. Тогда: «Перевод между счетами
  в разных валютах недоступен», кнопка выключена.
- Дано: состояние «Выполняется». Когда: повторное нажатие кнопки. Тогда: второй вызов
  перевода не уходит, поля не редактируются.
- Дано: в DEBUG/Preview включена мок-ошибка выполнения. Когда: перевод подтверждён.
  Тогда: шит «Не удалось выполнить перевод», балансы не изменились, новой операции
  в истории нет, режим ошибки сброшен.
- Дано: обычная сборка приложения. Когда: открыт шит подтверждения. Тогда: тестовых
  переключателей на экране нет.
- Дано: комментарий 100 символов. Когда: ввод продолжается. Тогда: лишние символы
  не вводятся, отдельная ошибка не показывается.
- Дано: шит успеха или повтора. Когда: нажата «Открыть в истории». Тогда: активной
  становится вкладка «История».
- Дано: шиты успеха и повтора. Когда: сравниваем расположение кнопок. Тогда: в обоих
  «Готово» сверху, «Открыть в истории» ниже — порядок совпадает.
- Дано: попытка завершена («Готово» / показан повтор / «Отмена» на ошибке).
  Когда: подтверждён следующий перевод — в том числе без правки полей.
  Тогда: используется новый ключ операции.
