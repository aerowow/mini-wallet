# 2026-08-29 — Общие секции REPORT.md и правки консистентности (PR #12, #13, #15 и этот)

## Задача

Собрать общие секции REPORT.md — зона сборщика отчёта по плану команды:
«Как была устроена работа», «Что не сработало у команды в целом», замер экрана
«Перевод» в «Замеры», названные пропуски необязательной части. Затем — серия
точечных правок консистентности по итогам адверсариальных ревью-прогонов отчёта.

## Как велась работа

Черновик общих секций писал агент по логам `sessions/` и истории git —
утверждения вида «мержи не трогали Core/» проверялись git-командами, не по
памяти. Дальше работа шла в связке с ревью-ассистентом: после каждого мержа
по свежему клону прогонялись параллельные read-only агенты (покрытие требований
ДЗ, фактчекер каждого числа, «злой грейдер», гигиена и сборка, трассировка
демо-сценариев PDF по коду), их находки вносились точечными правками. Суммарно
за день — три прогона ревью по 3–5 параллельных агентов, находки уходили
и владельцам чужих зон списками в чат.

## Промпты

Дословные тексты — в истории терминальной сессии; сюда перенесены по смыслу
(копии не сохранились при сборке лога в конце дня — сам факт честно
зафиксирован тупиком №4):

- «заполни общие секции REPORT.md по логам sessions/ и git-истории; каждое
  проверяемое утверждение подтверждай git-командой, а не по памяти»
- «покажи pwd репозитория, в котором ты правил REPORT.md, и текущую ветку;
  если это не ~/Desktop/mini-wallet — перенеси правки туда»

## Что не сработало (честно)

1. **Правки агента чуть не потерялись.** Агент заполнил секции, но оставил их
   незакоммиченными в рабочем дереве, а проверка смотрела только первую строку
   вывода `git status` и «не увидела» изменённый файл. Правки долго искали
   по чужим сессиям и чуть не переписали с нуля — всё это время они лежали
   в рабочем дереве. Урок: вывод `git status` читать целиком.
2. **`--amend` поверх запушенного мержа.** Точечная правка внесена через
   `git commit --amend`, когда HEAD уже стоял на мерж-коммите из origin —
   локальный main разошёлся с origin (ahead 1, behind 1). Разрулено без
   force-push: reset на origin/main, правки пересобраны обычным коммитом
   в новую ветку.
3. **Формулировка замера переписывалась трижды.** Первая версия называла
   длительность одним числом и читалась как «время работы над экраном» —
   удалена; вторая не отделяла машинное время генерации от ручной работы —
   добавлена явная граница; третья звучала оправданием — заменена нейтральной
   «методикой сравнения». Урок: цифра без явно названной методики читается
   неверно даже своими.
4. **Лог этой сессии собран в конце дня, а не по ходу** — поэтому промпты
   выше приведены по смыслу, а не дословно. У остальных участников логи велись
   по ходу работы — надо было так же.
