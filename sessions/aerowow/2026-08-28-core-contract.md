subagent-driven development: на каждую задачу свежий субагент-имплементер + отдельный

scoped-ревью.

## 4. Решения
- **Models.swift**: `Currency` (rub/usd + symbol "₽"/"$"), `OperationKind`
  (transfer/deposit), `OperationDirection` (incoming/outgoing), `OperationFailureReason`
  (differentCurrencies/executionFailed, с `shortText` для истории и `displayText` для
  формы), `OperationStatus` (success/failed(reason:)), `Account` (Identifiable,
  Hashable), `Operation` (Identifiable, Hashable, включая `direction` — пополнение →
  incoming, перевод → outgoing), `TransferRequest`, `TransferResult`
  (completed/duplicate/failed).
- **WalletStore** — единственный источник данных всех трёх экранов: `@MainActor
  @Observable final class`, создаётся один раз в `@main`, прокидывается через
  `.environment`; экраны читают тот же инстанс, SwiftUI перерисовывает сам.
- **MoneyFormatter** — единый формат денег во всём приложении, округление суммы через
  `NSDecimalRound(.plain, 2)` до передачи в `NumberFormatter` (двоичный double внутри
  форматтера мисокруглял пограничные суммы).
- **Реестр идемпотентности** в `WalletStore.transfer` хранит только успешные переводы
  (ключ → id операции); повтор ключа после ошибки выполнения проходит заново, повтор
  ключа после успеха возвращает `.duplicate(original)` без повторного изменения
  балансов.
- **`simulateExecutionFailure`** — одноразовый мок-переключатель под `#if DEBUG`: первый
  `transfer` после включения возвращает `.failed(.executionFailed)` и сам сбрасывает
  флаг; в Release-сборке свойства нет.
- **`totalRubBalance`** живёт в сторе (сумма балансов только ₽-счетов, без конвертации
  валют) — общий для экрана «Счета» и, при необходимости, других экранов.
- Группировка операций по датам и поиск/фильтрация — ответственность экрана «История»
  (Dev 3), в контракт Core не входят.
- Два зафиксированных расхождения, вынесенные за рамки контракта (стор одинаков в обоих
  вариантах, влияет только на форму):
  1. Жизнь ключа идемпотентности: ТЗ 02 говорит «после Готово форма очищается, следующее
     подтверждение получает новый ключ», уточнение (1) от 28.08 — «ключ не сбрасывается
     на успехе, форма не очищается». Решение — за Dev 2 + PM, они согласовывают между
     собой и поправляют ТЗ.
  2. Переключатель мок-ошибки (`simulateExecutionFailure`) существует только в
     DEBUG/Preview конфигурациях (ТЗ 02) — в Release не собирается и не отображается.

## 5. Что не сработало
- Код форматтера из исходного плана округлял через двоичный `double` внутри
  `NumberFormatter`: `Decimal("1.005")` давал «1,00» вместо «1,01». Найдено ревьюером
  задачи 2 эмпирической пробой конкретных значений; исправлено добавлением
  `NSDecimalRound(.plain, 2)` до форматирования (коммит `57b0869`).
- Код стора из исходного плана имел TOCTOU-гонку идемпотентности: `MainActor`
  реентерабелен на `await Task.sleep`, поэтому два одновременных вызова `transfer` с
  одним и тем же ключом оба проходили первую проверку реестра до паузы. Найдено
  ревьюером задачи 4; исправлено повторной проверкой реестра сразу после паузы плюс
  конкурентным тестом (`async let` ×2 с одним ключом → ровно один `.completed` и один
  `.duplicate`) (коммит `6981e9b`).
- Скрипт скилла task-brief не понимал русские заголовки задач («### Задача N») —
  автоматическое извлечение брифов не сработало, брифы для субагентов вытаскивались
  вручную через `awk` по номеру задачи.
- Красно-зелёный цикл TDD: на каждую из четырёх задач Core сначала писался
  `swiftc`-харнесс с падающими assertions (нет реализации / неверное округление / гонка
  не закрыта), затем — минимальная реализация до зелёного прогона; харнессы живут в
  некоммитируемой `tmp-tests/` и в репозиторий не попадают, финальный гейт перед PR —
  `xcodebuild`.
