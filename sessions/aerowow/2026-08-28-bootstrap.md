# Сессия 2026-08-28 — Bootstrap репозитория

## 1. Задача
Подготовить командный репозиторий для ДЗ №2: структура под 3 iOS-разработчиков + PM,
процессные документы, GitHub с защитой веток. Без кода — код каждый разработчик пишет
сам по ТЗ от PM.

## 3. Агенты
- Главная сессия Claude Code (планирование + исполнение).
- 1 × Plan-субагент: проработка деталей бутстрапа (формат project.pbxproj с synchronized
  folders, дизайн контракта, команды gh для branch protection). Часть результата
  (готовый Swift-код контракта и заглушек) была отброшена решением команды — см. п. 5.

## 4. Решения
- **Проект создан вручную в Xcode** (objectVersion 77, synchronized folders): новые файлы
  подхватываются без правок pbxproj → merge-конфликтов в pbxproj не будет.
- **Никакого кода в бутстрапе**: контракт Core команда пишет и согласовывает сама отдельным
  PR, после мержа он заморожен (правило в CLAUDE.md).
- **Материалы курса вынесены** из репозитория до git init (платный контент, публичный репо).
- **Корень репо** — папка с документами процесса, Xcode-проект — подпапка `mini-wallet/`.
- **Branch protection**: PR + 1 approve, force-push запрещён, `enforce_admins=false` —
  страховка на дедлайн (владелец может смержить без approve в крайнем случае).
- Ветки: `feature/accounts` (Dev 1 = aerowow), `feature/transfer` (Dev 2),
  `feature/history` (Dev 3), `docs/spec` (PM). Разработка — строго после ТЗ от PM.

## 5. Что не сработало
- Первый план агента предполагал написать весь каркас кода (контракт, стор, мок-данные,
  вью-заглушки) и рукописный project.pbxproj — отброшено: команда решила, что код пишет
  каждый сам, а проект проще создать в Xcode GUI. Урок: сначала фиксировать границы
  «что делает агент / что делают люди», потом просить план.
- Deployment target у созданного в Xcode проекта оказался 26.5 — собрать смогут только
  участники с Xcode 26.5; решение — понизить руками в настройках таргета (см. README).
- Схема Xcode по умолчанию не расшарена (лежит в xcuserdata) — на свежем клоне
  `xcodebuild -scheme` падает; чинится галочкой Shared в Manage Schemes.
