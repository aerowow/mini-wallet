# 2026-08-29 — Экран «Счета» тремя параллельными сабагентами (feature/accounts)

## Задача

Реализовать экран «Счета» по ТЗ `docs/specs/01-accounts.md` и макету
`design/accountsDesign.pdf` (+ `design/pen-dev-prompt.md`, шаг 3). Обязательный пункт ДЗ:
раздробить экран на три части и сделать их тремя параллельными сабагентами, каждому — только
его файлы, изоляция через отдельные git worktrees; затем собрать, проверить сборкой и
отчитаться о времени и потраченном контексте. Финал: commit + push + PR.

## Промпты дословно

Ключевой промпт человека (сокращён до содержательной части, вводные о ветках опущены):

```

2) сводный баланс "Всего" с логикой "валютный счет в сумму не входит" и мелкой сноской об этом
3) пустое состояние "Пока нет счетов" (кнопка перевести выключена) и превью с мок-данными

скажи сколько времени заняло и сколько контекста потратилось
```

Общий каркас промпта сабагентов (каждому подставлялись свой worktree, ветка, файлы и спецификация):


Индивидуальные части: сабагент 1 — `AccountCardView` + `AccountsListSection` («Мои счета»,

## Решения

- Prep-коммит с `AccountsDesignTokens.swift` ДО запуска агентов: общие токены цветов/шрифтов/
  геометрии + `.accountsCardBackground()`, чтобы три агента не разъехались по стилю. Caseless
  enum, не `extension Color` — все Features компилируются в один модуль.
- Каждому агенту — только свои файлы; композиция `AccountsScreen.swift` остаётся за
  оркестратором, поэтому каждый sub-worktree собирается автономно (стаб экрана не тронут).
- Сноска «Валютный счёт не входит в сумму»: в PDF-макете отсутствует, ТЗ 01 §3/§4 требует —
  расхождение решено в пользу ТЗ (карточка выше макетных 93pt).
- Пустое состояние: в PDF нет фрейма — построено по ТЗ + pen-dev-prompt (шаг 3, EmptyState);
  достижимо только через `WalletStore(accounts: [], operations: [])` в превью.
- Заголовок — кастомный `Text` 28pt (не NavigationStack: навигации с экрана нет, системный
  large title не 1:1 с макетом). Композиция — чистый VStack без ScrollView (контент ~480pt).
- `PrimaryButton` без параметра isEnabled: выключенность стандартным `.disabled()`, стиль
  читает `\.isEnabled`. Компонент живёт в `Features/Accounts/`; Dev 2 сможет переиспользовать
  (отмечено в PR — дублировать тип нельзя, один модуль).
- Context7: MCP-сервер подключён в конфиге, но в сессию инструменты не попали (сессия стартовала
  раньше) — использован его публичный HTTP API через WebFetch (search + llms.txt), в том числе
  каждым сабагентом по своей теме.

- По итогам ревью (10 подтверждённых находок, 0 отклонённых верификацией):
  `PrimaryButton` → `AccountsPrimaryButton` (все Features в одном модуле — одноимённый тип
  у Dev 2/3 дал бы redeclaration только после мержа обеих веток); шрифты токенов переведены
  на системные стили — размеры макета 28/34/17/15/13 совпали с дефолтами
  .title/.largeTitle/.body/.subheadline/.footnote, т.е. Dynamic Type достался без визуальных
  отличий (потолок `.accessibility2` на экране, т.к. вёрстка без ScrollView); карточка счёта
  объединена для VoiceOver (`.accessibilityElement(children: .combine)`); исправлен зазор
  `Spacer(minLength:)` внутри HStack со spacing (фактические 36pt → 12pt) и убран лишний
  frame; `background(_:in:)` вместо шейпа в кнопке; `.layoutPriority(1)` на сумме (строка
  с NBSP не переносится); превью пустого состояния — в свой файл; убран вложенный VStack
  секции.
- `AccountsSummaryView` осталась на `@Environment` — решение человека (буква ДЗ:
  «данные из WalletStore через .environment»).
