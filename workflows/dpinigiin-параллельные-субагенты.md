# Workflow: экран на трёх параллельных субагентах

**Автор:** dpinigiin (Dev 3) · **Повторяемая задача:** собрать экран приложения из нескольких
файлов силами параллельных субагентов, не получив конфликтов имён и правок в чужих зонах.

Процедура проверена на экране «История» (`mini-wallet/mini-wallet/Features/History/`):
8 файлов, три субагента, ≈ 212 тыс. токенов, 46 вызовов инструментов.
Факты и цифры — из `sessions/dpinigiin/2026-08-28-история.md`.

## Когда применять

- Экран режется на 3–4 независимых куска, между которыми мало связей (строка списка,
  вью-модель с фильтрами, пустые состояния).
- Общие модели и стор уже заморожены: агентам не нужно ничего согласовывать между собой.
- Есть ТЗ с критериями приёмки, по которым потом можно проверять, а не «смотреть, красиво ли».

## Когда не стоит

- Экран меньше трёх файлов: накладные расходы на контракт имён больше выигрыша.
- Куски связаны общим состоянием, которое ещё не спроектировано, — сначала спроектировать,
  потом резать.
- Контракт `Core` неполный: агенты начнут дописывать модели каждый по-своему.
- Задача читательская (разобраться, посчитать, найти) — субагенты тут не нужны,
  главная сессия справится дешевле.

## Шаг 1. Выписать контракт до кода

Отдельным промптом, **без единой строки кода**. Читать точечно, репозиторий не обходить.

> Прочитай ровно эти файлы: ТЗ экрана в `docs/specs/`, дизайн-промпт (нужный шаг),
> `Core/` — модели, стор, форматтер, стаб экрана в моей папке.
> Выдай коротко, без пересказа кода:
> 1. API, на котором строится экран: что отдаёт стор, поля модели, как считаются
>    вычисляемые свойства, какие тексты лежат в энумах, как форматировать деньги;
> 2. стартовые мок-данные списком, отдельно пометить нетипичные записи;
> 3. что из ТЗ входит в скоуп — да/нет по каждому пункту;
> 4. настройки проекта, которые важны для сборки (deployment target).
> Ничего не редактируй и не коммить.

На выходе — короткая справка, из которой дальше пишутся промпты субагентам. Здесь же
выясняется, хватает ли контракта: если чего-то нет, это стоп-сигнал, а не повод дописать
`Core` самому.

## Шаг 2. Разрезать экран на непересекающиеся зоны файлов

Зона = список конкретных файлов, а не «часть функциональности». Пример деления:

| Зона | Файлы |
|---|---|
| 1 | строка списка, группировка |
| 2 | вью-модель, чипы, шит фильтров |
| 3 | пустые состояния, превью |

Правило: **один файл принадлежит ровно одному агенту**. Пересечений быть не должно,
иначе двое перезапишут друг друга.

## Шаг 3. Зафиксировать контракт имён и раздать заранее

До запуска написать блок с точными именами типов и сигнатурами, которые агенты объявляют
и на которые ссылаются. Этот блок вставляется **всем троим дословно, одинаковым текстом**,
с пометкой, кто что объявляет, а кто только использует:

```
// Файл A (владелец — субагент 1)
struct HistorySection: Identifiable, Hashable { let id: String; let title: String; ... }
enum HistoryGrouping { static func sections(from:calendar:now:) -> [HistorySection] }

// Файл B (владелец — субагент 2)
@MainActor @Observable final class HistoryViewModel {
    var searchText: String
    func visibleOperations(in store: WalletStore) -> [Operation]
    ...
}

// Файл сборки (владелец — человек, НЕ ТРОГАТЬ)
struct HistoryScreen: View { init(viewModel: HistoryViewModel) }
```

Проверено: 12 зафиксированных имён — при сборке ни одного конфликта, чужие файлы править
не пришлось. Агент 3 писал превью, ссылающиеся на ещё не существующие типы, — это нормально
и должно быть разрешено явно, иначе он наплодит заглушек.

В каждый промпт добавить:

> Не запускай `xcodebuild` — параллельные сборки конкурируют за DerivedData, сборку прогоню я.
> Не трогай ничего вне своих файлов: `Core/` заморожен, корневые файлы и `pbxproj` не твои.
> В финальном ответе верни списком: созданные файлы, объявленные сигнатуры и **любые места,
> где ты отступил от контракта или ТЗ**.

Последнее требование обязательно — см. грабли.

## Шаг 4. Общий сборочный файл не отдавать никому

Файл, который связывает зоны (у экрана это корневая `View`), не отдаётся ни одному агенту.
Он пишется человеком после того, как все закончили: там видно фактические сигнатуры на диске,
и правки не конфликтуют.

Порядок: запустить **все вызовы субагентов одним сообщением** (иначе прогон станет
последовательным) → дождаться всех → `grep` по объявленным сигнатурам в созданных файлах →
написать сборочный файл под то, что реально на диске.

## Шаг 5. Сборка и прогон по критериям приёмки

1. Сборка:
   ```
   xcodebuild -project mini-wallet/mini-wallet.xcodeproj -scheme mini-wallet \
     -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
   ```
   Ошибки чинить только в своих файлах.
2. Прогон на симуляторе **по критериям приёмки из ТЗ**, пункт за пунктом, со скриншотом
   на каждый критерий. Не «посмотри, красиво ли»: формулировка проверки берётся из раздела
   «дано / когда / тогда».
3. Состояния, недостижимые на стартовых моках (пустая история), проверяются временной
   локальной правкой своего файла; после снимка правка откатывается и сборка повторяется.
   В логе отмечается, что кадр снят не с того кода, что в ветке.

Зелёная сборка не заменяет прогон: на «Истории» компилятор пропустил три расхождения с ТЗ —
обрезанные заголовки строк, счётчик фильтров за краем экрана и липкий заголовок,
перечёркнутый строками. Все три нашлись только на устройстве.

## Грабли

- **Дефолтный аргумент вне MainActor.** `init(viewModel: HistoryViewModel = HistoryViewModel())`
  не компилируется: выражение дефолтного аргумента вычисляется вне `MainActor`, а `@Observable`
  вью-модель им изолирована. Лечится двумя инициализаторами: `init(viewModel:)` и `init()`,
  который вызывает первый.
- **Симулятор ниже деплой-таргета.** `xcodebuild` падает с «Unable to find a destination
  matching the provided destination specifier» (exit 70), если загруженный симулятор старше
  `IPHONEOS_DEPLOYMENT_TARGET`. Перед прогоном: `xcrun simctl list devices available`,
  поднять подходящее устройство, собирать на его udid.
- **Кириллица не вводится в симулятор.** Ввод текста через автоматизацию принимает только
  ASCII, `simctl pbcopy` кладёт UTF-8 как MacRoman («ОТПУСК» → «–û–¢–ü–£–°–ö»). Рабочий обход:
  при активной русской раскладке ASCII-клавиши мапятся в кириллицу — `jngecr` → «Отпуск»,
  `ooo` → «Щщщ». Экранная клавиатура может отключиться в пользу аппаратной посреди прогона,
  тогда тапы по её координатам уходят «в список» вхолостую — проверять скриншотом.
- **Отступления субагентов принимаются молча.** Из трёх агентов трое отступили от контракта:
  добавили свойства на энумы, выбрали другой системный компонент, подставили системный цвет
  вместо отсутствующего токена. Ничего из этого не ломает сборку и не всплывает само — поэтому
  в промпте обязательно требовать явный список отступлений в финальном ответе и разбирать его,
  а не только смотреть на «готово».
- **Токен дизайна, которого нет в Assets.** Если Assets — чужая зона, агент подставит системный
  цвет. Это фиксируется в логе и PR, а не чинится вторжением в чужую папку.

## Что на выходе

- Готовый экран: файлы зон + собранный человеком корневой файл.
- Зелёная сборка и скриншоты по каждому критерию приёмки.
- Цифры для отчёта: время каждого субагента, токены, вызовы инструментов; выигрыш от
  параллельности считается как «сумма длительностей минус самый долгий агент» — это оценка,
  а не замер, если последовательный прогон не делался.
- Список отступлений агентов от контракта и список того, что нашёл прогон, а не компилятор.
