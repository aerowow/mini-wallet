# REPORT — ДЗ №2, команда Mini Wallet

## Как была устроена работа

**Контракт-first.** Сначала бутстрап без кода (PR #1): структура репозитория, правила
в `CLAUDE.md`, карта владения папками, branch protection. Затем — ТЗ от PM (PR #2,
ветка `docs/spec`), и только после них код. Общий контракт разложен на два core-PR
за один день: `core/contract` (PR #3) — модели, `WalletStore`, `MoneyFormatter`,
мок-данные; `core/shell` (PR #4) — `TabView`, `AppRouter` и стабы трёх экранов,
сразу разложенные по папкам владельцев. После мержа Core заморожен, правки — только
отдельным согласованным PR.

**Три feature-ветки параллельно.** `feature/accounts`, `feature/transfer`,
`feature/history` — каждая от общего контракта, у каждой свой набор субагентов
и свой прогон на симуляторе. Параллельные субагенты изолировались git worktree:
Dev 1 — `.claude/worktrees/accounts-sub{1,2,3}` с ветками-подзадачами, Dev 2 —
`git worktree add --detach` вне репозитория, без веток и коммитов; Dev 3 работал
без worktree, на непересекающихся файлах в рабочем дереве. Общий файл-композиция
экрана во всех трёх случаях оставался за оркестратором и никому не отдавался.

Стабы в папках владельцев сделали своё: за все три feature-ветки ни один PR
не изменил `Core/`, `mini_walletApp.swift` и `project.pbxproj`. Единственная правка
`pbxproj` после заморозки — 2 строки deployment target 26.0 отдельным согласованным
PR #5 до начала работы над экранами. Merge-конфликтов в проектном файле не было
ни одного.

**PR и кросс-ревью.** Прямые пуши в `main` запрещены, слияние — PR + минимум
1 approve от другого участника. Шаблон PR требует не только «что сделано», но и
разделы «Агенты и субагенты» (сколько, параллельно или нет, ссылка на лог) и
«Что не сработало (честно)», плюс чек-лист границ: контракт не тронут, правки
только в своей папке, .swift-файлы вручную в `pbxproj` не добавлены, лог сессии
на месте. Каждая сессия с агентами логировалась в `sessions/<логин>/` дословными
промптами, повторяемые процедуры — в `workflows/`.

**Координация в чате.** Всё, что выходило за карту владения, согласовывалось
до PR: правка настроек таргета, вопросы PM по контракту с ответами команды
(легли в план core-контракта), отклонение от ТЗ 02 по порядку кнопок в шитах.
Чужие находки в чужой зоне не чинились — фиксировались в отчёте и уходили
владельцу зоны: битая ссылка на `docs/MiniWallet-specs.pdf` в README (позже
убрана владельцем при обновлении README, PR #11; сам PDF добавлен PM в PR #16),
отсутствующий токен `positive` в `Assets.xcassets` (так и не добавлен).

### Что не сработало
- Первый план бутстрапа: агент собирался написать весь каркас кода (контракт,
  стор, мок-данные, вью-заглушки) и рукописный `project.pbxproj` — отброшено,
  команда решила писать код сама, проект создать в Xcode GUI. Урок: сначала
  фиксировать границы «что делает агент / что делают люди», потом просить план.
- Механика Xcode-проекта дала три сюрприза: `.gitkeep` в папках фич ломали
  сборку («Multiple commands produce .gitkeep» — синхронизированные папки
  копируют их в бандл); схема не была расшарена — на свежем клоне
  `xcodebuild -scheme` падал, а галочка Shared с первого раза не сохранилась;
  Xcode создал вложенный git-репозиторий, попавший в коммит пустой
  gitlink-ссылкой (вложенный `.git` удалён, папка переподключена).
- Код из исходного плана Core содержал два бага, которые нашли только
  субагенты-ревьюеры: округление денег через двоичный double внутри
  `NumberFormatter` (`Decimal("1.005")` → «1,00»; исправлено `NSDecimalRound`,
  коммит `57b0869`) и TOCTOU-гонку ключа идемпотентности — `MainActor`
  реентерабелен на `await Task.sleep`, два одновременных `transfer` с одним
  ключом проходили проверку реестра оба (исправлено повторной проверкой после
  паузы + конкурентный тест, коммит `6981e9b`).
- Скрипт скилла task-brief не понял русские заголовки задач («### Задача N») —
  брифы для субагентов вытаскивались вручную через `awk`.
- Фолбэк-команда выбора симулятора из брифа вернула первый попавшийся iPhone 14,
  для которого не было валидного destination схемы — UDID подбирался вручную
  (iPhone 17, iOS 26.2), команду из брифа один в один выполнить не удалось.
  Смоук оболочки прошёл только headless-скриншотом, без ручного прогона человеком.
- Гипотеза собственного лога бутстрапа («target 26.5, соберут только с
  Xcode 26.5+») не подтвердилась: 26.5 стоял лишь в project-level конфигурациях,
  target-level уже был 26.0 и перекрывал проект. Риск для проверяющих был меньше
  заявленного; правку довели до конца, потому что расхождение вводило в
  заблуждение в UI Xcode.
- Макеты не покрывают все состояния из ТЗ: на `accountsDesign` нет сноски про
  валютный счёт, на `historyDesign` — поиска и части фильтров-чипов. Смотреть
  их пришлось обходом (`Read` PDF не рендерит) — общий тупик с разбором
  бинарника описан в «Что не сработало у команды в целом».
- Plan-агент экрана «Счета» упал на середине из-за ухода машины в сон —
  возобновлён продолжением диалога (SendMessage) с того же места, без
  перезапуска с нуля.
- MCP-инструменты Context7 не попали в сессию (сервер подключён в конфиг, но
  сессия стартовала раньше) — обойдено публичным HTTP API через WebFetch,
  функционально равнозначно.
- `README.md` ссылался на несуществующий `docs/MiniWallet-specs.pdf` —
  ссылка замечена, но на месте не чинилась: файл вне зоны владения Dev 1.
  Резолюция: ссылка убрана владельцем при обновлении README (PR #11), сам PDF
  позже добавлен в репозиторий (PM, PR #16), и README снова на него ссылается —
  теперь на существующий файл.
- Три параллельных сабагента сдали зелёную сборку, но ревью-workflow подтвердил
  10 реальных проблем: от будущего redeclaration (`PrimaryButton` — все Features
  компилируются в один модуль, одноимённый тип у Dev 2/3 сломал бы сборку только
  после мержа обеих веток) до фактического зазора 36pt вместо 12pt из-за
  `Spacer(minLength:)` внутри HStack со spacing. Зелёная сборка ≠ чистый код.

## Dev 3 (dpinigiin) — История
### Что делал / какие агенты и субагенты
Экран «История» целиком: 8 файлов в `mini-wallet/mini-wallet/Features/History/` —
список операций из `WalletStore` с группировкой по дням и липкими заголовками, строка
операции, поиск по комментарию и сумме, быстрые чипы и шит фильтров, два пустых
состояния, пять `#Preview` экрана в `HistoryPreviews.swift` (плюс инлайн-превью
в файлах компонентов). `Core/`, корневые файлы и `pbxproj` не изменялись.

Работа шла тремя промптами: (1) разбор вводных без кода — чтение ТЗ `03-history.md`,
`design/pen-dev-prompt.md`, четырёх файлов `Core` и стаба экрана; субагенты не
запускались, объём чтения был известен заранее; (2) реализация субагентами;
(3) прогон на симуляторе и починка найденного.

**Три субагента, запущены одним сообщением — параллельно**, каждому только его файлы:

| # | Зона | Время | Токены | Вызовов инструментов |
|---|---|---|---|---|
| 1 | `OperationRow`, `HistoryGrouping` | 3 мин 09 с | 64 148 | 14 |
| 2 | `HistoryViewModel`, `HistoryFilterChips`, `HistoryFiltersSheet` | 5 мин 32 с | 80 943 | 19 |
| 3 | `HistoryEmptyStates`, `HistoryPreviews` | 2 мин 38 с | 66 875 | 13 |

Итого ≈ 212 тыс. токенов и 46 вызовов инструментов. Параллельный блок занял 5 мин 32 с
(по самому долгому), сумма длительностей — 11 мин 19 с, то есть выигрыш около 5 мин 47 с.

Общий `HistoryScreen.swift` не отдавался никому и собирался вручную после того, как все

### Что не сработало
- **Зелёная сборка не значит верный экран.** После сборки субагентских файлов
  `xcodebuild` проходил успешно, и на этом проверка была остановлена. Живой прогон
  нашёл три расхождения с ТЗ, которых компилятор не видит: обрезанные заголовки строк
  («Основной → Накопите…»), счётчик активных фильтров и «Сбросить», уезжавшие за правый
  край ряда чипов, и липкий заголовок дня, который перечёркивался строками при прокрутке.
  Все три — визуальные, все три нашлись только на устройстве.
- **Липкие заголовки: два отката подряд.** Сначала заголовку секции добавлен
  `.background`, затем `.listRowBackground` — в обоих случаях строки `List` в iOS 26
  рисуются поверх закреплённого заголовка. Обе правки выброшены, список переведён
  на `ScrollView` + `LazyVStack(pinnedViews: [.sectionHeaders])`.
- **Ошибка компиляции в собранном вручную файле:** `init(viewModel: HistoryViewModel =
  HistoryViewModel())` не собирается — выражение дефолтного аргумента вычисляется вне
  `MainActor`, а вьюмодель им изолирована. Разнесено на два инициализатора.
- **Потеряна сборка на неподходящем симуляторе:** первый booted-симулятор — iPhone 13 mini
  с iOS 18.1, ниже деплой-таргета 26.0; `xcodebuild` завершился с «Unable to find a
  destination matching the provided destination specifier» (exit 70). Пришлось поднимать
  iPhone 17 / iOS 26.5. Всего за сессию 11 запусков сборки, 3 неуспешных.
- **Три отступления субагентов от выданного контракта**, принятые как есть:
  субагент 2 добавил `var title` на два энама фильтров; субагент 3 собрал пустые состояния
  на `ContentUnavailableView` вместо ручной вёрстки; субагент 1 покрасил входящие суммы
  системным `.green`, потому что токена `positive` в `Assets.xcassets` нет, а Assets —
  чужая зона. Ни одно отступление не ломало сборку, но контракт формально не был соблюдён.
- **Кириллицу в симулятор автоматизацией не ввести:** ввод текста принимает только ASCII,
  `simctl pbcopy` кладёт UTF-8 как MacRoman («ОТПУСК» → «–û–¢–ü–£–°–ö»). Часть запросов
  набиралась тапами по экранной клавиатуре, пока та не отключилась в пользу аппаратной —
  несколько тапов ушло «в список» вхолостую. Рабочий обход нашёлся случайно: у симулятора
  активна русская раскладка, поэтому ASCII-клавиши мапятся в кириллицу (`jngecr` → «Отпуск»,
  `ooo` → «Щщщ»).
- **Пустое состояние недостижимо на стартовых данных:** «Операций пока нет» проверялось
  временной правкой `HistoryScreen` (`if true` вместо `store.operations.isEmpty`); скриншот
  `07-net-operacij.png` снят на этой правке, правка откачена, сборка пересобрана.
  То есть один из семи скриншотов снят не с того кода, который лежит в ветке.
- **Липкость заголовков осталась непроверенной.** После перехода на `LazyVStack` семь
  мок-операций помещаются на экран целиком, прокручивать нечего — требование ТЗ
  «липкие заголовки» подтверждено только тем, что используется штатный `pinnedViews`.
- **Необязательные пункты (изоляция с выводом отказа, инъекция на двух моделях, отчёт
  по инструментам) не выполнялись** — в логах сессии их нет, цифр по ним нет.

## Что не сработало у команды в целом

- **`.gitkeep` ломал сборку.** Пустые папки фич держались `.gitkeep`-файлами;
  синхронизированные папки Xcode копируют их как ресурсы в корень бандла, три
  одинаковых имени дали «Multiple commands produce .gitkeep». Файлы убраны из дерева
  приложения, пути папок зафиксированы текстом в `CLAUDE.md` — папка появляется
  в git с первым файлом разработчика.
- **Вложенный git-репозиторий от Xcode.** При создании проекта Xcode завёл свой
  репозиторий внутри командного; папка проекта попала в коммит пустой ссылкой-gitlink,
  то есть содержимого проекта в репозитории фактически не было. Вложенный `.git`
  удалён (там был только авто-коммит Xcode), папка переподключена к основному
  репозиторию.
- **Нерасшаренная схема валила `xcodebuild` на свежем клоне.** Схема по умолчанию
  лежит в `xcuserdata` и в репозиторий не попадает — команда сборки из `CLAUDE.md`
  у остальных участников падала бы сразу. Чинится галочкой Shared в Manage Schemes,
  но с первого раза она не сохранилась: файл схемы появляется только после закрытия
  окна.
- **Разбор PDF-макетов из бинарника — тупик, в который по очереди сошлись двое.**
  `Read` макеты не открывает («pdftoppm is not installed»), poppler/pdftotext/mutool
  в системе нет, и оба разработчика по очереди начали доставать геометрию и цвета
  прямо из content stream: Dev 1 — Explore-агентом по `accountsDesign.pdf`, Dev 2 —
  распаковкой zlib-потоков и разбором операторов `Tj`/`rg`/`re` в `transferDesign.pdf`.
  Второй заход остановлен человеком. Все нужные числа — отступы, радиусы, типографика,
  зоны нажатия — лежали текстом в `design/pen-dev-prompt.md`, а сами макеты смотрятся
  штатным `qlmanage -t`. Урок: при наличии текстового источника тех же чисел в бинарник
  не лезть.
- **Тапы по симулятору из терминала невозможны без Accessibility.** В `xcrun simctl`
  команды тапа по координатам нет (список подкоманд проверен), `idb` и `cliclick`
  не установлены, System Events отвечает `osascript is not allowed assistive access`.
  Выдавать Accessibility всей машине ради одного прогона команда отказалась, поэтому
  все прогоны — ручные: человек тапал, агент снимал кадры `xcrun simctl io booted
  screenshot`. Смоук оболочки по этой же причине подтвердил только дефолтное
  состояние таб-бара, без переключения вкладок. Отдельная плата — ввод: кириллицу
  автоматизацией в симулятор не передать; подробности и случайно найденный обход —
  в разделе Dev 3.
- **Зелёная сборка не значит верный экран — совпало у всех троих.** У Dev 1
  ревью-workflow после успешной сборки подтвердил 10 реальных проблем, у Dev 3
  живой прогон нашёл три расхождения с ТЗ, которых компилятор не видит, у Dev 2

### aerowow — worktrees и изоляция с выводом отказа

В логах фигурируют минимум 5 git worktree:

Зафиксирован 1 реальный отказ изоляции: попытка сложить превью PDF-макетов в
scratchpad за пределами воркитри была отклонена — команда сочтена слишком

и ручное удаление до коммита. Вывод: изоляция действительно блокирует запись за
границы воркитри, причём проверка срабатывает и на безопасной команде, если не
может её проанализировать, — обход потребовал ручных шагов.

в логах нет, в отчёт не включены.
